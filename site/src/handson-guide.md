## Claude で提供されるアプリの違い

なんとなく、凄さを伝えたところで、 **Claude** で使えるサービスを紹介（おさらい）しましょう。

- Claude では次の3つのツールが使えます
  - 1. Claude (Claude AI)
    - ChatGPTやGeminiみたいに、チャットができます
    - Claudeは、インタラクティブなグラフ（＝動くグラフ）をチャットの中に埋め込んでくれる機能もあります
  - 2. Claude Code
    - スーパーエンジニアのように、コーディングができます
    - AIエージェントが自律的にコードをかいて、パソコンの操作をすることもできます
    - 調べ物をしたり、ファイルの操作を自動化したり、Webページやアプリを作ったり、本格的なシステムを作ることもできます
  - 3. Claude Cowork
    - **2026年4月10日に一般公開されました！** 🎉
    - Claude Code と同じように、全自動でタスクを実行してくれる
    - タスクを指示したら、成果物を作るところまで実行して、結果を報告してくれます。つまり、 **※途中の承認は無しでやり切ってくれる！**

### 「ChatGPT と何が違うの?」

ChatGPT を使い込んでいる方からよく聞かれる質問です。ざっくりこんな違いがあります。

| | ChatGPT | Claude Code / Cowork |
| --- | --- | --- |
| **作業場所** | ChatGPT のサーバー側 (毎回アップロード必要) | **自分のパソコンの作業フォルダ** で直接 |
| **業務ツール連携** | カスタム GPT は外接続限定的 | **MCP** で Notion / Slack / GitHub / Google ドライブと直結 |
| **対話スタイル** | 質問→回答の往復 | **対話的に何度も微修正** (コード) / 指示したら **全自動で完走** (Cowork) |
| **自分仕様の拡張** | カスタム GPT (Web UI 限定) | スキル + プラグイン + サブエージェント (テキスト 1 枚で配布可能) |

> 💡 ざっくり言うと、ChatGPT が **「相談相手」** なのに対し、 Claude Code は **「自分のパソコンと業務ツールの両方を触れる同僚」** に近いイメージです。

具体的にどう違うか:
- **副業 SNS 運用**: ChatGPT に投稿文を書かせ → コピペで楽天ROOM に貼る (2 ステップ) / Claude Code: 「Notion の販売記録を読んで、楽天ROOM 用の投稿文をフォルダに保存して」 (1 メッセージで完結)
- **個人サロン**: ChatGPT に「予約管理ファイル」をアップロード → 質問 / Claude Code: 「予約フォルダを見て今月の傾向を教えて」 (アップロード不要)

## Claude デスクトップアプリで「コード」を試してみましょう

それでは、いよいよ Claude Code を体験していきましょう！

### Step 1: デスクトップアプリを起動する

- **Claude デスクトップアプリ** を起動します（事前準備でインストール済みのはず）
- ログインしていなければ、ログインしましょう
- 画面の左上にボタンがいくつか並んでいます。今日はこの中の **「コード」** と **「Cowork」** を使います

![](assets/claude-app-code.png)

### Step 2: 作業フォルダを準備する

**Claude Code** は自律的に動き回るので、作業場所として **専用フォルダ** を作っておきましょう。

- デスクトップなどお好きな場所に **新規フォルダ** を作成してください（例: `my-handson` という名前）
  - Mac の場合: デスクトップで **右クリック → 「新規フォルダ」** で作成できます
  - Windows の場合: デスクトップで **右クリック → 「新規作成」 → 「フォルダー」** で作成できます
- このフォルダは「Claude Code が読んだり書いたりしてOKな範囲」になります

### Step 3: 「コード」タブを開いて、フォルダを指定する

- 画面左上の **「コード」** ボタンをクリックします
- 作業フォルダを聞かれるので、Step 2 で作成したフォルダを選択します
- 入力欄が表示されたら準備完了です

### Step 4: 試しに話しかけてみよう

それでは、試しに **Claude Code** に話しかけてみましょう！入力欄に下記を打って Enter:

```
こんにちは！　今日はいい天気ですね！
```

何か返信があれば成功です 🎉🎉🎉🎉🎉🎉

![](assets/say-hello-claude-code.png)

時間が余った方は、もう少し **Claude Code** との会話を楽しんでみてください。

### Step 5: 「許可しますか？」画面に出会ったら

Claude Code が **ファイルを書き換えたり、新しいソフトをインストールしたり、外部にアクセスしたり** する直前に、 **「許可しますか？」** という確認画面が表示されることがあります。今日のハンズオンでは、Claude にお願いをして作業が始まったタイミングでよく出会います。

![](assets/do-you-want-to-proceed.png)

ここで大事なポイントは **2つ** です。

1. **中身を読まずに「許可」を連打しない！**
   - 何をしようとしているか、ざっくりでいいので確認しましょう
   - よく分からないコマンドが出てきたら、 **Claude Code に「これは何をするコマンド？」と聞いてもOK** です
2. **「常に許可」は慎重に！**
   - 「一度だけ許可」は今回だけ許可、「常に許可」は今後ずっと許可という意味です
   - 慣れないうちは **毎回「一度だけ許可」で1つずつ確認** するのがおすすめです

## 安心して使うためのコツ

とても便利な Claude Code ですが、正しく使わないと危険なこともあります。

例えば、こんなことが起きるかもしれません。

- 🔑 **APIキーやパスワードが漏れちゃう**
  - 例えば「画像を生成したい！」と思って、Claude Code に言われるがまま APIキー（サービスを使うための秘密の鍵）を設定ファイル（`.env`）に保存したとします。セキュリティがガバガバだと、Claude Code がそのファイルの中身をうっかり外部に送信してしまう可能性があります。APIキーが漏れると、 **他人にあなたのアカウントを勝手に使われて、高額な請求が来る** なんてことも…！
- 🗑️ **大事なファイルを勝手に消されちゃう**
  - 「フォルダを整理して」とお願いしたら、Claude Code が「これは不要だな」と判断して、実は大切だったファイルを削除してしまう…なんてことも。
- ⚙️ **知らないソフトを勝手にインストールされちゃう**
  - Claude Code はパソコンに対する命令を実行できます。「この機能を使うにはこれが必要です、インストールしますか？」と聞かれて、よく分からないまま「OK」を押し続けていると、意図しないソフトがどんどん入ってしまうかもしれません。

> 😱 怖い！と思った方、 大丈夫です。これらはすべて **「専用フォルダで作業して、許可画面をちゃんと見る」** だけで防げます。 顧客データや家計簿のような **作業フォルダの外にあるファイルには触れません** 。 次の 4 つを意識するだけで、ぐっと安全になります。

![](assets/security-risks.png)

### 🛡️ コツ①：作業フォルダを限定する

先ほど「新規フォルダを作って、その中で作業しましょう」とお伝えしました。
これは快適に使うためだけでなく、 **セキュリティ的にもとても大事** です。

Claude Code は、指定したフォルダの中にあるファイルを読んだり、書き換えたりできます。
もし **デスクトップ全体** や **パソコンの一番上のフォルダ（ホームフォルダ）** を作業フォルダにしてしまうと、関係のないファイルまで触れてしまいます。

> ✅ **専用のフォルダを作って、その中で作業する** ← これだけで安全性がグッと上がります！

### 🛡️ コツ②：モード(動き方)を理解する

「コード」タブには、入力欄のそばに **モードを切り替えるセレクタ** があります。Claude の動き方を 4 段階で選べます。

| # | モード | 動き | おすすめの人 |
| --- | --- | --- | --- |
| 1 | **許可を確認** (デフォルト) | 危ない操作の前に「許可しますか？」と都度確認 | **初心者はこのまま** |
| 2 | **編集を承認** | ファイル編集は自動で進めるが、コマンド実行などは都度確認 | コードの修正を素早く回したい人 |
| 3 | **プランモード** | 実行はせず、計画だけを提示してくれる | 「いきなり作業されるのは不安」な人 |
| 4 | **自動モード** | 何も確認せず、最後まで自動で進む | 信頼できる定型作業 (上級者向け) |

> 💡 **プランモード** は「いきなり作業を始めずに、まず手順を見せてください」という指示モードです。送信ボタン近くのセレクタをクリックして選ぶか、 **キーボードの数字キー (1/2/3/4)** でも切り替えられます。 (※ ターミナル版でおなじみの `Shift + Tab` は Desktop アプリでは使えません)

慣れないうちは **「許可を確認」のまま** が一番安心。慣れてきたらプランモードで計画確認、信頼できる作業は自動モード、と使い分けましょう。

![](assets/desktop-mode-selector.png)

### 🛡️ コツ③：「許可しますか？」の判断基準

「許可を確認」モードでは、危ない操作の前に「許可しますか？」画面が出ます。

> 💡 **判断に迷ったら、許可 を押す前に Claude にこう聞いてください**: 
> 「これは何をしますか? 私のパソコンに何か影響ありますか?」
> Claude が分かりやすい日本語で説明してくれます。**「分からないまま 許可 を押さない」** これだけ守れば OK です。

ざっくりの目安 (コマンドが読める方向け):

| 多くは安心 ✅ | 慎重に確認 ⚠️ |
| --- | --- |
| 作業フォルダ内のファイルを読み書きする | フォルダの外を **削除** しようとする |
| ライブラリのインストール (`npm install` 等) | `sudo` で始まるコマンド (パソコン全体に影響) |
| ローカルで完結する Git の保存 | **外部にデータを送る** ような操作 |
| ブラウザでローカルファイルを開く | パスワード・API キーを読み出す操作 |

> 💡 「常に許可」は **慎重に**。 慣れないうちは毎回 一度だけ許可/拒否 で確認する方が安全です。

### 🛡️ コツ④：秘密の情報の扱い

> 💡 **`.env` ってなに?**
> パスワードや API キー（サービスを使うための秘密の鍵）を書いておくための「環境設定ファイル」。アプリやスクリプトから読み込んで使います。
>
> **`.gitignore` ってなに?**
> 「GitHub にアップロードしたくないファイル」の一覧を書くファイル。ここに `.env` を入れておくと、間違って公開する事故を防げます。

今日のハンズオンでは使いませんが、今後 Claude Code を使っていくと `.env` ファイルを扱う場面があるかもしれません。
このファイルをうっかり **GitHub（みんなが見れる場所）にアップロード** してしまうと、秘密の情報が全世界に公開されてしまいます。

> 💡 もし今後 `.env` を使うことがあったら、 **Claude に「.env を .gitignore に追加して」と頼む** だけでOKです！覚えておくと安心です。

## ちょっと応用的な使い方にチャレンジ

> 💡 **プランモードを使ってみよう**
> 「コツ②」で紹介した **プランモード** は応用テクニックの中でも特におすすめです。モードセレクタからプランモードに切り替えてからお願いすると、Claude はまず計画だけを示してくれます。内容を読んで「OK」と返すと実行が始まります。 **最初の数回はプランモードで試して、Claude が何をするつもりかを確認する** クセをつけると安心です。

### スラッシュコマンド

`/` から始まるコマンドで、Claude Code に特別な指示が出せます。

「コード」タブの入力欄で `/` を押すと、候補が表示されます。↑↓キーで選択できます。

```
(例) Desktop アプリで使えるコマンド
/help   : 使えるコマンドの一覧を表示
/clear  : 会話をリセットする
/model  : Claude の AI モデルを切替えられる
/usage  : 使用量を確認できる
/memory : 覚えてもらった内容 (CLAUDE.md) を確認・編集
/agents : サブエージェントの一覧を見る
/mcp    : 外部接続 (MCP) の状態を見る
```

> 💡 **ターミナル版にしかない** コマンドもあります (`/config` や `/sandbox` などはターミナル専用で、 Desktop アプリでは反応しません)。

![](assets/slash-commands.png)

### スキルで Claude を「自分仕様」に拡張する

スラッシュコマンドの中には、 **スキル** という仕組みで増やせるものがあります。

> 💡 **スキルってなに?**
> Claude Code の機能を後付けで増やせるパーツです。Markdown ファイルで定義されていて、 `.claude/skills/` フォルダに置くだけで `/スキル名` で呼び出せるようになります。

#### 代表的なスキル

| スキル | 何ができる? |
| --- | --- |
| **`/frontend-design`** | AIっぽくない、おしゃれな Web デザインを作ってくれる |
| **pdf** | PDF を読んだり作ったり、編集したりできる |
| **xlsx / docx / pptx** | Excel・Word・PowerPoint ファイルを扱える |
| **web-design-guidelines** | UI のアクセシビリティ・使いやすさをチェックしてくれる |

> 💡 デスクトップアプリでもスキルは同じように使えます。`/` を押してスキル名を選ぶだけ。

#### 自分だけのスキルを作る `/skill-creator`

「いつも同じ手順で作業しているな…」と思ったら、その手順を **自分のスキル** にしておくと、次から `/自分のスキル名` で一発呼び出しできます。

```
/skill-creator
```

このコマンドを実行すると、Claude があなたと対話しながら **オーダーメイドのスキル** を作ってくれます。

- 例: 「楽天ROOM の朝コレ投稿を作る」スキル → `/asakore`
- 例: 「教室のチラシを作る」スキル → `/kyoshitsu-flyer`
- 例: 「議事録を要約して Slack 用に整える」スキル → `/minute-summary`

> 💡 これは ChatGPT にはない **「自分仕様にカスタマイズできる」** Claude Code の強みです。中級者以上の方は、ぜひハンズオン後に試してみてください。

### プラグインで「作業環境ごと」配布する

スキルが便利なのは分かりましたが、 **スキルを 10 個まとめて、サブエージェントや MCP の設定も一緒に、1 ファイルで配布したい** ということもあります。それを叶えるのが **プラグイン** です。

> 💡 **プラグインってなに?**
> スキル・サブエージェント・MCP サーバー・設定をまるごとパッケージにしたもの。 「あなた専用の作業環境」 を 1 ファイルで配れるイメージです。

- **スキルとの違い**: スキル = 1 個の機能。 プラグイン = 機能のセット
- **インストール先**: Desktop アプリの **「プラグインを管理」** から、公式マーケットプレイスや友人が作ったものを追加できます
- **配布例**: 「楽天ROOM 運用パック」 「個人サロン経営パック」 など、業務に合わせた組み合わせが想像できます

### MCP で外の世界とつなぐ

Claude Code は **MCP** (Model Context Protocol) という共通の作法で、 **外部のシステムと直接やりとり** できます。

> 💡 **MCP ってなに?**
> 「Claude Code を Notion / Slack / GitHub / Google ドライブ などにつなぐためのコンセント」のような仕組みです。

| MCP でできること (例) | 業務イメージ |
| --- | --- |
| Notion を読み書き | 商品台帳から今日の値下げ候補を出してもらう |
| Slack に投稿 | 作業完了をチームの Slack に自動報告 |
| GitHub に連携 | ソースコードの変更履歴を見ながら修正案を作る |
| Google ドライブを読む | 議事録を読んで要約してくれる |

> 💡 **ChatGPT との違い**: ChatGPT は「相談相手」、Claude Code は MCP を介して **「あなたの業務ツールをそのまま使える同僚」** になります。

設定は `.mcp.json` という小さなファイル 1 つを作るだけ。 (難しそうですが、Claude に「Notion の MCP を設定して」と頼めば手順を案内してくれます)

### サブエージェントで「分身」を雇う

Claude Code の中で **小さな AI 同僚を呼び出して、別の頭で作業させる** ことができます。これが **サブエージェント** です。

> 💡 **サブエージェントってなに?**
> Claude が「ちょっとこの調査だけ別の人に任せたい」というときに呼び出す、 **専門特化した小さな AI 同僚** のこと。

#### 何が嬉しいの?

- **メインの会話を汚さない**: 大量の調査結果や下書きが流れ込んでこないので、メインの Claude との会話は軽いまま
- **並列で動かせる**: 3 体のサブエージェントを同時起動して、別々の仕事をさせられる
- **役割を分担できる**: 「調査担当」「計画担当」「校正担当」のように専門化させられる

#### 個人経営・副業での活用イメージ

最近ネットでは「Claude Code で **1 人会社** を作る」という話題が出ています。具体的には:

- **広報担当のサブエージェント**: 毎日 SNS 投稿のネタを 3 つ提案
- **経理担当のサブエージェント**: 月末に Notion から売上を集計
- **営業担当のサブエージェント**: 問い合わせメールに下書き返信を用意

メインの Claude は **「社長」** として全体を見ながら、 細かい作業をサブエージェントに振る、というイメージです。 副業や個人事業の方には特に効果が大きい使い方です。

呼び出しは `/agents` コマンドから管理できます。

### 🧰 まとめ: Claude Code を「自分の会社」にする道具たち

| 道具 | 役割 | 例 |
| --- | --- | --- |
| **スキル** | 1 つの便利機能 | `/frontend-design` |
| **プラグイン** | スキルや設定を **まるごと** 配布 | 「楽天ROOM 運用パック」 |
| **MCP** | **外の世界** とつなぐ | Notion / Slack / GitHub |
| **サブエージェント** | **分身** を雇う | 広報担当・経理担当・営業担当 |

> 💡 全部を一気に覚える必要はありません。まずはスキルから 1 つ試して、慣れたら他にも手を伸ばす、で十分です。

![](assets/company-toolkit.png)

### Claude Code を使うときのコツ

Claude Code をもっと上手に使うためのコツを紹介します。

- **指示は具体的に書く**
  - ❌「いい感じにして」 → Claude Code は何をすればいいか分かりません
  - ✅「自己紹介ページを作って。名前は○○、趣味は△△」 → 具体的なほど良い結果に！
- **一度にたくさん頼みすぎない**
  - 「あれもこれも全部やって！」よりも、1つずつお願いした方がうまくいきます
  - 大きな作業は、ステップに分けて指示しましょう
- **うまくいかなかったら、やり直してOK**
  - 思った結果と違ったら「やっぱり○○に変えて」と伝えれば大丈夫です
  - 何度でもやり直せるのが Claude Code の良いところです
- **困ったら Claude Code 自身に聞く**
  - 「このエラーはどういう意味？」「次は何をすればいい？」と聞けば、Claude Code が教えてくれます

## Claude デスクトップアプリで「Cowork」を試してみましょう

ここまでは「コード」タブで Claude Code を体験してきました。次は **Cowork** を試してみましょう。

### Cowork ってなに？

**Cowork** は、Claude Code のさらに進化版のような機能です。

> 🎉 **ニュース**: Claude Cowork は **2026年4月10日** に一般公開されました！

「コード」タブとの一番の違いは…

| | コード | Cowork |
| --- | --- | --- |
| 操作スタイル | 対話しながら少しずつ進める | 指示したら **全自動で最後までやり切る** |
| 「許可しますか？」 | 都度確認 | 最初に作業内容の確認はあるが、それ以降は **基本止まらない** |
| 向いている場面 | プレビューを見ながら微修正したい | 成果物がはっきりしていて一気に作りたい |

### Step 1: 「Cowork」タブを開く

- 画面左上の **「Cowork」** ボタンをクリックします（Step 1 と同じ場所、「コード」のとなりにあります）

![](assets/claude-app-cowork.png)

### Step 2: タスクを指示する

成果物が **明確なお願い** が Cowork は得意です。

```
(例) 「手作りアクセサリーショップ Hana」のチラシをHTMLで作ってください。
雰囲気: 和モダン・落ち着いた色合い・親しみやすさ
記載する情報: ショップ名、コンセプト、3つのおすすめ作品、SNSリンク、お問い合わせ
```

### Step 3: 進捗を見守る (途中で止めることもできる)

指示を出したら、あとは **待つだけ** です。Claude が自動的に作業を進め、完成したら結果を報告してくれます。

- 画面に **作業のログ** (今どのファイルをどう変えているか) が流れます。何をやっているか見守るのも楽しいです
- **「思っていたのと違う方向に進んでいる」** と気づいたら、画面上の **停止ボタン** で途中で止められます
- 止めたあとに「やっぱりこういう方向で」と追加指示を出して再開することもできます

> 💡 全自動とはいえ、 **見張っていなくても大丈夫** ですし、 **見張って止めても大丈夫** です。安心して使ってください。

### Step 4: 完成した成果物を使ってみる

Cowork が「できました！」と教えてくれたら、 **作業フォルダ** に成果物が保存されています。次の一歩はこんな感じ:

| 成果物 | 次にやること |
| --- | --- |
| **HTML ファイル (チラシ・ホームページ)** | Claude に「ブラウザで開いて」と頼む / 印刷したいときは「Cmd + P → PDFとして保存」 |
| **画像・GIF** | Finder (Mac) / エクスプローラー (Windows) から開く |
| **テキスト・Markdown (SNS 投稿文など)** | コピーして SNS の投稿欄に貼り付け |
| **動画ファイル** | ダブルクリックで再生 |

> 💡 「これどう使うんだっけ?」と分からなくなったら、 **Cowork に聞いてOK** です。「いまできた○○を、どうやって使えばいい?」と聞くと教えてくれます。

### Cowork が向くタスク / 向かないタスク

| 向くタスク 🎯 | 向かないタスク 🤔 |
| --- | --- |
| チラシ・告知ページなど成果物が明確 | 「いい感じにして」など曖昧な指示 |
| 動画の無音カット+字幕など定型処理 | デザインを見ながら少しずつ調整したい場合 |
| 調査して記事にまとめる | 途中で気が変わって方向転換したい場合 |

> 💡 「途中で確認しながら進めたい」というときは **「コード」タブ** に戻ってきましょう。

## 付録 A: (上級者向け) ターミナル/CLI で Claude Code を使う

ここから先は **ターミナル（黒い画面）で Claude Code を使ってみたい方向け** の参考情報です。
当日のハンズオン本編は終わっていますので、興味のある方だけ進んでください。

ターミナル版は **最新機能がいち早く登場する** のがメリットですが、コマンド操作に慣れる必要があります。

### A-1. ターミナルの基本操作

ターミナルを操作するのが初めてな方向けに、基本だけ紹介します。

- ターミナルの基本的な使い方
  - マウス操作は ほぼ 使えません...
  - 1つ前のコマンドをもう一度使いたいときは **↑ キー** を押します
  - **(重要)** 処理を中断するときは **control + c**  ※ `Command` ではなく `Control`
  - 終了するときは **赤い x ボタンでウィンドウを閉じる** でもOK
- ターミナルを使うときの注意点
  - **Enter** キーを押すときは慎重に。ちょっと怖いコマンドも実行できてしまうかも？
  - **半角/全角 どっち？** かを意識しましょう。通常は **半角モード**
- ターミナルの便利な使い方
  - (Macの場合)フォルダを **Dockのターミナルのアイコンにドラッグ＆ドロップ** すると、そのフォルダでターミナルを開けます
  - 作業したいフォルダに移動するには、`cd ` (シー ディー スペース) と入力した後にフォルダをドラッグ＆ドロップして Enter

![](assets/terminal-basics.png)

### A-2. Claude Code (CLI版) をインストールする

ターミナルで次のコマンドを実行してインストールします。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

> (参考) [Claude Code クイックスタート](https://code.claude.com/docs/ja/quickstart)

![](assets/claude-code-install.png)

### A-3. Claude Code を起動する

1. 作業場所として **新規フォルダ** を作成
2. そのフォルダを **Dock のターミナルに ドラッグ＆ドロップ**
3. 次のコマンドで起動

```bash
claude
```

最初は「アカウントへのログイン」等が求められます。 **↑↓矢印キーで選択** → **space** で選択 → **Enter** で決定 と操作します。

無事に起動できると、こんな画面が表示されます↓

![](assets/hello-claude-code.png)

### A-4. 終了するには

```bash
/quit

# または
/exit

# それか esc キーを 2回 連続で入力する
```

### A-5. No Flicker モード（画面のちらつき防止）

Claude Code (CLI版) は初期状態だと文字が表示されるときに画面がチカチカすることがあります。
**No Flicker モード** を有効にすると、スムーズに表示されるようになります。

```bash
CLAUDE_CODE_NO_FLICKER=1 claude
```

毎回入力するのが面倒な方は、こちらの設定方法を参考にしてください:

```bash
echo 'export CLAUDE_CODE_NO_FLICKER=1' >> ~/.zshrc
source ~/.zshrc
```

> 詳しくは [No Flicker モードの設定ガイド](./no-flicker-setup.md) を参照してください。

### A-6. サンドボックスモード `/sandbox`

CLI版では、Claude Code が触れるファイルやインターネット接続を制限する **サンドボックス** が使えます。

```
/sandbox
```

| モード | 説明 |
|---|---|
| **auto-allow** | 安全なコマンドは自動で実行してOK |
| **regular** | 安全なコマンドでも毎回確認してから実行 |

> 初心者の方は **regular モード** がおすすめです。詳しくは [サンドボックスモード設定ガイド](./sandbox-mode.md) を参照。
